# Обмен iCase CRM ↔ сайт (WooCommerce)

## Что работает
- **CRM → сайт** (функция `site-sync`, раз в 2 минуты по расписанию, если включено «Выгружать на сайт»):
  - цены и остатки товаров с отметкой «На сайте»; наличие = сумма по складам, отмеченным в «Настройки → Сайт»;
  - новые товары создаются на сайте (черновиком или сразу опубликованными — настройка), с категорией, характеристиками и фото;
  - б/у техника: каждый экземпляр — отдельная карточка, артикул `U-<IMEI/серийный>`, в названии состояние и АКБ, в описании — диагностика;
  - товар снят с сайта / продан / в архиве → карточка уходит в черновик, остаток 0;
  - на существующих карточках меняются только цена, остаток и видимость: описание и фото на сайте не перезаписываются;
  - сопоставление: по `woo_id`, иначе по артикулу (SKU, затем штрихкод, затем `CRM-xxxxxxxx`).
- **Сайт → CRM** (функция `site-api`):
  - `POST /functions/v1/site-api/woo-order` — веб-хук WooCommerce «Заказ создан» и «Заказ обновлён». Подпись `X-WC-Webhook-Signature` проверяется ключом API из CRM;
  - `POST /functions/v1/site-api/order` — тот же формат заказа для любого сайта, заголовок `X-Api-Key`;
  - `GET /functions/v1/site-api/feed` — каталог JSON (цены, наличие, характеристики, без закупочных цен), заголовок `X-Api-Key` или `?key=`.
- **Заказ с сайта**: клиент находится или создаётся по телефону, товар резервируется со складов сайта на склад «Резерв · сайт» (экземпляры — статус «в резерве»). В CRM раздел «Заказы»: подтвердить → провести продажу (канал «Сайт», без кассовой смены) или отменить (резерв снимается). Статус «Выполнен» или «Отменён» уходит обратно на сайт. Отмена на сайте снимает резерв автоматически.

## Безопасность
- Ключи WooCommerce (Consumer key и secret) и ключ API хранятся в Supabase Vault. Вводит их только владелец, наружу они не отдаются.
- Служебные функции (`site_feed`, `site_config`, `site_order_upsert` и др.) доступны только сервисной роли edge-функций.
- Расписание вызывает `site-sync` с внутренним токеном из Vault. Вручную функцию может запустить только владелец или управляющий.
- **152-ФЗ:** заказы содержат персональные данные покупателей. Принимать заказы с настоящего сайта можно только после переезда базы на российский сервер. Выгрузка цен и остатков персональных данных не содержит.

## Подключение
1. WooCommerce → Настройки → Дополнительно → REST API → «Добавить ключ», права «Чтение/Запись» → вставить в CRM: «Настройки → Сайт».
2. В CRM отметить склады для сайта, включить выгрузку, нажать «Выгрузить всё заново».
3. Заказы (после переезда базы): WooCommerce → Веб-хуки → два веб-хука («Заказ создан», «Заказ обновлён»), адрес — из CRM, секрет — ключ API из CRM; в CRM включить «Принимать заказы».

## Файлы
- `db/mig_site.sql` — таблицы, функции, расписание (применено в Supabase как `icase_v3_site_*`).
- `supabase/functions/site-sync/` — выгрузка на сайт; `supabase/functions/site-api/` — приём заказов и фид.
- `supabase/functions/tests/local_test.ts` — проверка на поддельном WooCommerce (21 проверка).
